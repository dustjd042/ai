## 1. 개요

OWASP LLM Top 10은 대규모 언어 모델을 사용하는 애플리케이션의 주요 보안 위험을 정리한 목록입니다. 모델뿐 아니라 데이터, 검색 시스템, 외부 도구, 권한, 출력 처리까지 함께 점검해야 합니다.

## 2. 취약점과 대응 방법

### LLM01. Prompt Injection — 프롬프트 인젝션

**설명**

사용자 입력이나 외부 자료에 포함된 명령이 모델의 원래 업무와 동작을 바꾸는 문제입니다. 웹페이지·문서·도구 응답을 통해 들어오는 간접 주입도 포함됩니다.

**예시**

문서 요약 봇이 문서 안의 “내부 자료를 외부로 전송하라”는 문장을 실행 지시로 받아들입니다.

**대응 방법**

- 외부 콘텐츠의 출처를 표시하고 업무 지시와 구분합니다.
- 도구 호출 시 서버에서 권한과 인자를 다시 검증합니다.
- 민감정보 접근과 외부 전송 기능을 제한합니다.
- 검색 결과·도구 응답·메모리를 통한 주입도 테스트합니다.

**핵심:** 금지 프롬프트만으로 완전히 방어할 수 없습니다. 주입에 성공해도 피해가 제한되도록 설계해야 합니다.

참고: [2026 공식 PDF](https://genai.owasp.org/download/56857/?tmstv=1785822482).

### LLM02. Sensitive Information Disclosure — 민감정보 노출

**설명**

LLM 응답을 통해 개인정보, 인증정보, 내부 문서 등 공개하면 안 되는 정보가 노출되는 문제입니다.

**예시**

고객 상담 봇이 다른 고객의 연락처와 상담 내역을 답변에 포함합니다.

**대응 방법**

- 모델에 전달하기 전에 불필요한 개인정보와 비밀값을 제거하거나 마스킹합니다.
- 사용자별로 접근 가능한 데이터만 조회하도록 서버에서 통제합니다.
- 응답과 로그에 민감정보가 포함되는지 점검합니다.
- 외부 모델 제공자의 데이터 보관·학습 사용 정책을 확인합니다.
- 학습 데이터에 실제 운영 비밀값을 포함하지 않습니다.

**핵심:** 민감정보가 불필요하게 모델의 입력에 들어가지 않도록 먼저 제한합니다.

참고: [OWASP 민감정보 노출 상세 지침](https://genai.owasp.org/llmrisk/llm022025-sensitive-information-disclosure/).

### LLM03. Excessive Agency — 과도한 실행 권한과 자율성

**설명**

LLM에 필요 이상의 기능·권한·자율성을 부여하여 잘못된 판단이 실제 시스템 피해로 이어지는 문제입니다.

**예시**

조회용 상담 봇에 결제 취소 권한까지 부여하여 잘못된 요청으로 결제가 취소됩니다.

**대응 방법**

- 조회와 변경 도구를 분리하고 필요한 도구만 제공합니다.
- 실행 계정에는 최소 권한을 부여합니다.
- 범용 셸 실행보다 범위가 제한된 업무 API를 제공합니다.
- 결제·삭제·외부 발송 등 중요한 작업은 실행 내용을 확인받습니다.
- 권한 검사는 LLM 판단과 별개로 API에서 수행합니다.

**핵심:** 모델이 작업을 제안하더라도 실행 가능 여부는 서버가 결정해야 합니다.

참고: [OWASP 과도한 자율성 상세 지침](https://genai.owasp.org/llmrisk/llm062025-excessive-agency/).

### LLM04. Supply Chain — 공급망 위험

**설명**

외부 모델, 데이터셋, 라이브러리 등 의존 요소의 취약점이나 변조가 애플리케이션에 영향을 주는 문제입니다.

**예시**

검증되지 않은 모델 파일이나 패키지를 도입하면서 악성 동작이 함께 유입됩니다.

**대응 방법**

- 모델과 패키지는 신뢰할 수 있는 배포처에서 확보합니다.
- 버전과 파일 해시를 고정하고 제공되는 서명을 검증합니다.
- 의존성 취약점과 라이선스를 점검합니다.
- 모델·데이터셋·패키지의 출처와 변경 이력을 관리합니다.
- 외부 구성 요소는 격리 환경에서 검증한 뒤 운영에 반영합니다.

**핵심:** 애플리케이션 코드뿐 아니라 모델과 데이터의 공급 경로도 관리합니다.

참고: [OWASP 공급망 상세 지침](https://genai.owasp.org/llmrisk/llm032025-supply-chain/).

### LLM05. Data and Model Poisoning — 데이터 및 모델 오염

**설명**

학습·미세조정·임베딩 등에 사용하는 데이터를 조작하여 모델의 응답이나 행동을 왜곡하는 문제입니다.

**예시**

지식 문서에 조작된 환불 정책이 들어가 챗봇이 잘못된 기준을 안내합니다.

**대응 방법**

- 데이터 출처와 수집·수정 권한을 관리합니다.
- 신규 데이터는 검토와 검증을 거쳐 반영합니다.
- 데이터와 모델의 버전 및 변경 이력을 보관합니다.
- 변경 전후 응답 품질과 보안 동작을 비교합니다.
- 오염 발견 시 이전 데이터와 모델로 복구할 수 있도록 준비합니다.

**핵심:** 모델 평가뿐 아니라 데이터 등록·수정 과정의 통제가 필요합니다.

참고: [OWASP 데이터 및 모델 오염 상세 지침](https://genai.owasp.org/llmrisk/llm042025-data-and-model-poisoning/).

### LLM06. Unbounded Consumption — 제한 없는 자원 소비

**설명**

요청량이나 처리 비용에 제한이 없어 자원 고갈, 서비스 지연, 과도한 API 비용이 발생하는 문제입니다.

**예시**

긴 입력과 반복 요청으로 추론 비용이 급증하거나 서비스가 응답하지 못합니다.

**대응 방법**

- 사용자별 요청 횟수와 동시 실행 수를 제한합니다.
- 입력 크기, 출력 토큰, 처리 시간을 제한합니다.
- 사용자·조직별 사용량과 비용 한도를 설정합니다.
- 비정상적인 사용량 증가를 탐지하고 차단합니다.
- 비용과 지연 시간을 지속적으로 모니터링합니다.

**핵심:** 요청 횟수뿐 아니라 요청 한 건이 소비할 수 있는 자원에도 상한이 필요합니다.

참고: [OWASP 자원 소비 상세 지침](https://genai.owasp.org/llmrisk/llm102025-unbounded-consumption/).

### LLM07. Misinformation — 잘못된 정보 생성

**설명**

사실과 다른 내용을 그럴듯하게 생성하여 사용자의 판단이나 후속 처리를 잘못 유도하는 문제입니다.

**예시**

존재하지 않는 API나 규정을 실제로 존재하는 것처럼 설명합니다.

**대응 방법**

- 검증된 자료를 검색해 답변 근거로 제공합니다.
- 출처가 실제로 답변 내용을 뒷받침하는지 확인합니다.
- 근거가 부족하면 답변을 보류하도록 설계합니다.
- 중요한 판단은 사람이 검토합니다.
- 도메인별 평가 데이터로 사실 정확도를 측정합니다.

**핵심:** RAG를 사용해도 검색 실패나 잘못된 해석으로 오류가 발생할 수 있습니다.

참고: [OWASP 잘못된 정보 생성 상세 지침](https://genai.owasp.org/llmrisk/llm092025-misinformation/).

### LLM08. Hidden Context Exposure — 숨겨진 컨텍스트 노출

**설명**

시스템 프롬프트 등 사용자가 직접 볼 수 없는 내부 컨텍스트가 노출되는 문제입니다.

**예시**

모델이 내부 운영 지침이나 숨겨진 설정을 응답에 포함합니다.

**대응 방법**

- 숨겨진 컨텍스트에도 비밀키와 비밀번호를 넣지 않습니다.
- 인증·인가 정책은 서버 코드에서 강제합니다.
- 응답에 내부 컨텍스트가 노출되는지 검사합니다.

**핵심:** 내부 지시가 비공개라는 가정에 보안을 의존하지 않아야 합니다.

참고: [2026 공식 PDF](https://genai.owasp.org/download/56857/?tmstv=1785822482).

### LLM09. Vector and Embedding Weaknesses — 벡터 및 임베딩 취약점

**설명**

RAG의 벡터 저장소와 검색 과정에서 접근 통제나 데이터 격리가 부족하여 정보가 노출되거나 검색 결과가 조작되는 문제입니다.

**예시**

같은 벡터 DB를 사용하는 다른 회사의 내부 문서가 검색되어 답변에 포함됩니다.

**대응 방법**

- 사용자·조직·문서 단위의 접근 권한을 관리합니다.
- 권한 조건을 벡터 검색에 적용하여 허용된 문서만 반환합니다.
- 필요에 따라 조직별 저장소나 네임스페이스를 분리합니다.
- 문서의 출처와 등록·수정 권한을 검증합니다.
- 권한이 다른 계정으로 교차 검색 테스트를 수행합니다.

**핵심:** 의미가 유사한 문서라도 현재 사용자가 읽을 권한이 없으면 반환하면 안 됩니다.

참고: [OWASP 벡터 및 임베딩 상세 지침](https://genai.owasp.org/llmrisk/llm082025-vector-and-embedding-weaknesses/).

### LLM10. Improper Output Handling — 부적절한 출력 처리

**설명**

LLM 결과를 검증 없이 화면·DB·실행 환경에 전달하여 기존 애플리케이션 공격으로 이어지는 문제입니다.

**예시**

생성된 HTML을 그대로 표시해 XSS가 발생하거나, 생성된 명령어를 서버에서 실행합니다.

**대응 방법**

- LLM 출력도 외부 입력과 동일하게 검증합니다.
- 화면 출력은 문맥에 맞게 인코딩하고 HTML은 정제합니다.
- SQL은 문자열 결합 대신 매개변수 바인딩을 사용합니다.
- 생성된 명령어나 코드를 운영 서버에서 바로 실행하지 않습니다.
- 구조화된 응답은 스키마와 업무 규칙을 모두 검증합니다.

**핵심:** JSON 형식이 올바르더라도 값이나 실행 내용은 위험할 수 있습니다.

참고: [OWASP 출력 처리 상세 지침](https://genai.owasp.org/llmrisk/llm052025-improper-output-handling/).

## 3. 실무 적용 체크리스트

아래는 앞선 대응 원칙을 구현 점검 항목으로 정리한 것입니다.

- [ ] 모델에 불필요한 개인정보·인증정보를 전달하지 않는다.
- [ ] 데이터 조회와 도구 실행 권한을 서버에서 검사한다.
- [ ] 외부 문서와 도구 응답을 신뢰할 수 없는 입력으로 취급한다.
- [ ] 조회 기능과 변경 기능의 권한을 분리한다.
- [ ] 중요한 변경 작업은 실제 실행 내용을 확인받는다.
- [ ] 검색 단계에서 사용자·조직별 문서 접근 권한을 적용한다.
- [ ] 모델 출력의 형식과 업무 규칙을 모두 검증한다.
- [ ] 요청량·토큰·처리 시간·비용에 한도를 설정한다.
- [ ] 모델·데이터·패키지의 출처와 버전을 관리한다.
- [ ] 변경 후 정확도·정보 유출·권한 우회 테스트를 수행한다.
- [ ] 로그에 비밀값이 남지 않도록 관리한다.
- [ ] 이상 동작 발생 시 중단·권한 회수·복구 절차를 마련한다.
